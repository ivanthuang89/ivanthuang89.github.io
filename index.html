AI Workflows

Most leaders adopt AI as a personal productivity tool. I operationalized it across a 200-person company — building production-grade skills, automations, and reporting infrastructure that run weekly without my involvement.

What was built

Four deployed skills, a skills hub, a daily automation, and a weekly adoption report — all in production, all actively used.

Meta LP
Audit
Pre-launch compliance skill
Built for the sales and creative team. Claude reviews a Meta landing page against DealMaker's compliance checklist before any campaign goes live. Catches issues that previously only surfaced after launch — after spend had already been wasted.
Delegation
Brief
Work distribution skill
Structured prompt that takes a deliverable and generates a brief each recipient can upload into their own Claude session and execute independently. Used for documentation sprints, knowledge base builds, and any project requiring contributions from people who weren't in the original meetings.
Daily
Standup
Slack canvas automation
Automated daily standup that writes directly to a Slack canvas used as a live task tracker. The canvas updates without anyone touching it — open it, see where things stand. Built to replace the weekly status meeting that produced the same information a day late.
Intake
Triage
Inbound request management skill
Built for orgs where high-frequency, mixed-priority requests arrive without routing logic. The skill categorizes incoming asks into three lanes (immediate, scheduled, delegated) and surfaces the right next action without requiring a meeting to triage it.
Skills
Hub
Internal deployment infrastructure
An HTML page deployed to Cloudflare Pages that surfaces all four skills in one place — instructions, trigger phrases, and usage examples. Built so any team member can find and use the right skill without asking Ivan what prompts to run. The distribution layer for everything above.
Adoption
Report
Weekly product usage reporting
Automated weekly report posted to a Slack channel tracking adoption of CPT, CIP, and Morpheus across the org via Userpilot. The report that surfaced the Morpheus #1-of-15 stat and the CIP crossover moment — both of which became executive talking points.

The pattern

Every workflow followed the same logic: identify where the team was spending time on something that shouldn't require a person, build the minimum viable automation, deploy it, and measure adoption.

How each workflow was built
1

Identify the friction

Not "where can we use AI" but "where is the team doing something repetitive that produces a known output." Pre-launch reviews, status updates, request routing — all had predictable outputs.

2

Write the skill in Claude

Each skill is a Claude prompt with a trigger phrase, a structured output format, and a scope definition that tells it exactly what to include and exclude. No code, no API calls — just precise instruction sets.

3

Deploy via skills hub

Skills land in the hub so anyone can find them. The hub is a single HTML page on Cloudflare — no login, no onboarding. Open it, find the skill, run it.

4

Measure and report

The adoption report tracked weekly usage across all tools. That data became the evidence used to justify continued investment in internal tooling — and was cited directly in ELT conversations.

The distinction

Most performance leaders are using AI to write emails faster. This is different — structured skills that run on a schedule, produce a consistent output, and don't require me to touch them. The question isn't whether you can use AI. It's whether you can build something with it that works when you're not in the room.
